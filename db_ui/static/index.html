Optimization history

Changes carried from the original trader into the current Pump trader, plus recent fixes. Verified against repository history and current implementation; individual dates are omitted where history groups several changes into one commit.

Implemented
All implemented optimizations and execution fixes (23)
  1. V1 source compatibility — Normalize binary v1 inline accounts and instructions into the read-only source decoder; preserve source config metadata without additional RPC calls. Copies retain local budget settings and the existing legacy builder. Live sub-1 ms p95 remains unverified.
  2. Source-instruction routing — Build Pump.fun and PumpSwap copies directly from the observed instruction and rewrite copier accounts locally; removed pool discovery, route catalogs, account scans, live quotes, and pool-cache maintenance.
  3. No pre-send simulation — Skip simulation and pre-send fee RPC checks; submit through Sender with skipPreflight and no retries. Landed failures can still cost fees.
  4. Source mint evidence — Reuse successful source transaction evidence for classic SPL and Token-2022; inspect extensions in the background and cache validated fallback mint reads.
  5. Shared decode context — Parse account keys and instructions once across decode passes; decode mint strings once and use constants for fixed program and tip addresses.
  6. Binary live metadata — Keep LaserStream inner instructions as bytes and loaded addresses as public keys, avoiding a base58 encode/decode round trip. RPC recovery keeps its JSON path.
  7. Debug-only diagnostics — Collect detailed instruction inspection data only when debug logging is enabled.
  8. Cached associated token addresses — Reuse canonical ATA derivations from a bounded cache keyed by owner, mint, and token program.
  9. Prewarmed volume PDAs — Cache Pump.fun and PumpSwap user-volume addresses by program and wallet; prewarm source and copier addresses at startup.
  10. Warm blockhash cache — Warm before ingestion, refresh in the background, and use fresh cached blockhashes on the trade path with expiry and remaining-validity checks.
  11. Background balance cache — Refresh wallet balances outside execution, overlap initial balance and mint preparation, and use targeted RPC only for missing or stale entries.
  12. Reliable cache updates — Invalidate affected balances on submission and confirmation, refill from reconciliation, and prevent older background responses from replacing newer data.
  13. Persistent WSOL reuse — Keep the WSOL account open, spend fresh cached WSOL first, wrap only the shortfall, and retain sell proceeds as WSOL. Startup and background reads warm the WSOL cache.
  14. Ordered background journal — Enqueue observation, intent, reservation, transaction, and outcome writes to a separate ordered writer instead of awaiting SQLite commits before submission. Queued records carry an abrupt-shutdown loss risk.
  15. Immediate duplicate claims — Claim source signatures in memory and seed claims from persisted attempts at startup, preserving duplicate protection without waiting for a reservation commit.
  16. Background timing writes — Use a separate bounded timing queue and batch up to 32 records before passing writes to the ordered journal, so timing persistence does not hold up execution.
  17. Nonblocking console output — Send logs to a bounded background writer; slow console I/O does not block the trade worker. Full queues can drop logs.
  18. Warm Sender connections — Warm the connection at startup and ping periodically to reduce cold-connection overhead.
  19. Regional Sender configuration — Use the Newark regional Sender endpoint alongside the configured LaserStream region. Network response time remains separate from local receipt-to-send latency.
  20. Microsecond latency visibility — Record decode, queue, routing, build, sign, serialization, and receipt-to-send microseconds. The latency command reports p50/p95/p99 and the fraction below 1 ms; the flow UI shows landed timing averages.
  21. PumpSwap exact-output slippage fix — Apply the slippage-adjusted token target to buy and buy_v2 while preserving the copied SOL input cap.
  22. Capped input sizing — Clamp larger buys to the configured maximum instead of skipping them. Current SOL maximum is 0.05; smaller buys retain their calculated size. Fees, tips, and rent are additional.
  23. Background settlement — Confirm and reconcile up to 64 submitted copies in parallel while preparation and submission stay ordered. Reserve pending input, fees, tips, and rent so overlapping copies cannot reuse funds.
  24. Position-relative exits — Copy the source sold fraction against the copier token position using source pre-sell balances, without adding a separate source balance RPC.

01 Receive & queue

Recorded timings ingestion_queue_ms — payload receipt to worker start, including decoding, journaling, and queue wait. database.record_observation — journal write.

Sync workDecode binary stream metadata

Keep inner instruction data as bytes and loaded addresses as public keys. Avoid base58 encoding followed by decoding on the live path; RPC recovery retains JSON/base58 support. Detailed instruction diagnostics are collected only with debug logging. payload_decode_us measures this stage.

Awaited asyncRecord observation → enqueue

The background journal accepts the observation before it enters the bounded execution queue. Database commits run separately. A full execution queue waits for capacity. observation_enqueue_us measures observation handling; queue_wait_us measures enqueue to worker pickup.

Worker prepares and submits one observation at a time. Submitted copies confirm and reconcile in background tasks while the next observation proceeds.

Sync workDecode intent & check policy

Reject stale signals and disallowed trades. Persist out-of-scope sources as unsupported, with a reason, then continue to the next observation.

Concurrent · awaitedSource mint evidence + cached balance

Both Pump.fun and PumpSwap reuse successful source mint evidence, including Token-2022 metadata. Extension validation runs in the background. Missing or ambiguous evidence falls back to mint RPC. Native balance lookup overlaps mint preparation; a missing or stale cache entry requires RPC.

Decode the DEX program, discriminator, account metas, source wallet, source token accounts, and source balance delta. Pump.fun BuyV2 requires 27 accounts and SellV2 requires 26; both use copier-derived user accounts during rewrite.

Awaited asyncSize, cap & reserve attempt

Percentage or fixed buy sizing is clamped to the input token’s maximum_input. The local SOL cap is 0.05; fees, tips, and account rent are additional. Smaller copies keep their size; inputs below the minimum are skipped. Exits mirror the source sold fraction. Duplicate reservation prevents a second submission of the same source signature; this is not a wallet balance reservation.

03 Build a route

Recorded timings route_wall_ms and route_ms — elapsed source build time. route_instruction_build_ms — rewriting and instruction construction. route_instruction_build_us — local account rewriting and instruction construction. Older records may contain WSOL check timers.

Sync workEstimate output & apply slippage

Expected output is floor(copy_input × source_output / source_input). Apply configured slippage (currently 50% locally). Exact-input buys and sells encode a minimum output. PumpSwap buy/buy_v2 request that adjusted output with the copied input as the spending cap; they may spend less. This source-price estimate is not a fresh pool quote.

Sync workRewrite accounts with cached wallet PDAs

Replace source wallet, token, and volume accounts with copier accounts. Volume PDAs are cached by program and wallet and prewarmed for the source and copier at startup. ATA addresses also use a cache. Preserve pool, curve, vault, fee, and program accounts.

Sync workFund persistent WSOL from cached balance

PumpSwap keeps the canonical WSOL ATA open. Buys reuse fresh cached WSOL and wrap only the input shortfall; a missing or stale WSOL entry uses zero cached funds. ATA creation is idempotent. Sells leave proceeds as WSOL. Account validation happens at startup; there is no trade-time WSOL account check RPC. cached_wsol_lamports and wrap_lamports record funding.

Shared preparationCached blockhash

Current mainnet routing reads a warm blockhash from memory. If it is unavailable, the route fails; the background refresher fetches new blockhashes. Account creation uses idempotent ATA instructions.

Timing route_shared_preparation_ms: shared blockhash lookup.

Source account rewriting and local WSOL funding preparation finish before transaction building and signing.

Sync work · mainnetSelect priority fee & tip

The mainnet path uses the configured fixed priority fee. It builds fee and tip instructions locally.

Sync workBuild, sign & serialize

Build with cached blockhash, fixed priority fee, and configured tip. Sign the exact transaction submitted. Microsecond timers include transaction_build_us, transaction_sign_us, and serialization_us.

06 Confirm & finish

Recorded timings confirmation_ms — confirmation polling and landing-slot persistence. reconciliation_ms — resulting balance reads, transaction-specific output checks, and outcome persistence. DB operations: record_landed_slot, update_attempt. Logging and timing-writer enqueue have no separate stage timer.

Background · per submitted copyConfirm → record slot → reconcile → save outcome

After Sender acknowledgment and journal enqueueing, a background task polls confirmation, persists the landing slot, refreshes balances, checks output from that transaction’s metadata, and saves the outcome. The submission worker takes the next observation immediately. Up to 64 settlement tasks can overlap; at that limit the worker waits for one to finish.

Sync workLog timings & try enqueue

Log formatting runs on the submission worker for skipped observations and on settlement tasks for submitted copies; console I/O uses a bounded, nonblocking background writer. Timing JSON is offered to the background writer with a nonblocking queue operation. Settlement tasks retain the complete per-copy timings, including confirmation and reconciliation.

Alongside the worker

BackgroundJournal commits & mint validation

Observation, intent, reservation, and transaction persistence enqueue work for a separate journal task. Commits retain SQLite WAL and full durability. Enqueue failure is surfaced; queued writes can be lost on abrupt shutdown. Mint extension inspection runs separately with cached results; a first source-evidence copy can submit before validation completes.

Current limits

Preparation and Sender requests remain ordered. Confirmation and reconciliation run in background tasks. Pending balance reservations and the 64-task limit can hold back new copies during bursts. Cache misses can add pre-send RPC latency. No creator liquidity-pull screening is implemented. Recent PumpSwap exact-quote-input WSOL transfer failures remain unresolved.

BackgroundTiming writer

A separate task awaits database commits. It batches up to 32 available records from a 256-record queue. The trade does not await these writes.

Queue overflow or write failure can drop telemetry with a warning. Graceful shutdown drains settlement tasks and the timing writer before the journal; abrupt shutdown can lose pending timing records. Recovery data never uses this queue.

Timing No per-trade timer for background telemetry writes. db_total_us sums measured DB operations; db_pre_send_us snapshots that sum before sending, and db_post_send_us is the remainder. These are operation totals, not wall-clock stages.

BackgroundWallet balance cache

Refresh SOL and tracked token accounts with positive or unknown balances 500 ms after each refresh finishes. New token accounts are tracked on demand. A missing or older-than-one-second entry triggers a targeted balance read. WSOL refreshes even at zero; other known zero-balance token accounts are not polled while idle. Submission and confirmation invalidate affected entries; reconciliation updates them immediately from RPC. Older background responses cannot overwrite newer reads. During an overlapping batch, tracked input accounts use the original balance minus reserved debits rather than waiting for another RPC read. RPC refreshes cannot credit this budget until settlement completes. Per-account reservations deduct pending input, WSOL, tips, worst-case priority fees, and a conservative 0.01 SOL rent/base-fee budget per copy. Debits remain reserved until the overlapping batch finishes; affected cache entries are then invalidated. Ambiguous submissions retain their budgets until restart recovery.

BackgroundBlockhash cache refresh

Warm the cache before signal and execution workers start, then refresh one second after each completed refresh. Fetch confirmed blockhash and block height together, with a 1.5-second timeout and more than 20 blocks of remaining validity.

Entries expire two seconds after request start. Failed refreshes do not extend freshness; a cold or stale trade-time lookup fails until the background refresh succeeds. Fresh lookups do not wait for background refresh. Maintenance stops with the service.

Timing No separate per-trade timer for background refresh. Cached preparation is measured by route_shared_preparation_ms.

BackgroundSender connection warming

Mainnet startup warms the Sender connection. Periodic pings then run alongside the worker, waiting 30 seconds between completed warmups.

Timing No separate per-trade timer for startup warmup or background pings.

Reading the timings

Use receipt_to_send_start_us to compare send latency. A displayed 0 ms is rounded down, not zero work. Run pump-copy-trader latency --limit 100 for p50/p95/p99 and the fraction below 1,000 µs. Sender response time is separate from local submission latency. DB and route substage durations can overlap; adding them does not reconstruct a timeline. Build substages include elapsed work on failures and cancellation. Unstarted timers are omitted; older records may lack newer fields. DB operation entries contain elapsed microseconds and call counts; other fields use milliseconds unless labeled _us.

Averages are computed separately from available samples for each field, so missing historical timers appear as dashes. Unsupported observations are recorded without submitting a transaction.
