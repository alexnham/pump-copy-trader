Awaited async · sequentialJournal → enqueue

record_observation finishes before the observation enters the bounded execution queue. A full queue waits for capacity. The source then awaits update_cursor, which may overlap the worker.

Worker handles one observation at a time, through confirmation and reconciliation.

02 Prepare the trade

Recorded timings preparation_ms — worker start through policy checks, initial reads, sizing, input balance check, and attempt reservation. cache_lookup_ms — access to a source pool snapshot in the background catalog. DB operations: mark_intent, reserve_attempt, and mark_skipped on an early exit.

Sync workDecode intent & check policy

Reject stale signals and disallowed trades. Persist out-of-scope sources as unsupported, with a reason, then continue to the next observation.

Concurrent · awaitedWrite intent

mark_intent runs alongside the initial RPC reads. Its write must succeed before reserving or routing.

Concurrent · awaitedMint evidence or mint RPC + SOL balance

Fast Pump.fun SOL buys use the successful source transaction’s classic SPL token metadata (mint_from_source=1, mint_read_ms=0). Other paths inspect mint accounts by RPC. The cached native SOL balance lookup runs alongside the mint work.

Sync workExtract source instruction

Decode the DEX program, discriminator, account metas, source wallet, source token accounts, and source balance delta. Pump.fun BuyV2 requires 27 accounts and SellV2 requires 26; both use copier-derived user accounts during rewrite.

Join intent write + mint evidence/read + input balance → size trade → reserve.

Awaited async · required gateReserve attempt

reserve_attempt must succeed. A duplicate reservation ends this attempt before submission.

03 Build a route

Recorded timings route_wall_ms — elapsed routing time, including discovery. route_ms excludes discovery-only waits. route_quote_ms appears for adapter quotes; direct Pump.fun instruction copies are included in route_wall_ms without a separate quote timer.

Sync work · direct pathEstimate source ratio

For source-direct mode, expected output is copy_input × source_output / source_input. The minimum output applies configured slippage. No pool reserve or live DEX quote is required.

Sync work · direct pathRewrite Pump.fun accounts

Replace the source user and token accounts. For V2 buys and sells, derive the copier base/quote ATAs and user_volume_accumulator; preserve curve, fee, vault, and program accounts. Sells use the copier's token amount and minimum quote output.

Concurrent · awaited · quoted pathSource validation → quote

Pool-based routes validate the source pool, read adapter state, and construct swap instructions. If the source fails, try cached routes and discovery; alternative candidates can race. Direct instruction copies skip this step.

Timing route_source_pool_fetch_ms: cached source snapshot lookup plus validation. route_quote_ms: adapter state reads, quote calculation, and swap instruction construction.

Shared preparationCached blockhash

Current mainnet routing reads a warm blockhash from memory. If it is unavailable, the route fails; the background refresher fetches new blockhashes. Account creation uses idempotent ATA instructions.

Timing route_shared_preparation_ms: shared blockhash lookup.

Direct instruction copy or pool quote joins cached blockhash preparation before signing.

Sync work · mainnetSelect priority fee & tip

The current mainnet path uses a configured fixed price for source-direct copies or a cached price for other routes. It builds fee and tip instructions locally.

Timing Older records may contain route_fee_estimation_ms from the former RPC-based fee path.

Sync workBuild & sign transaction

Apply fee instructions and sign the exact transaction that will be sent.

Timing Included in route_ms; signing has no separate recorded timer.

04 Validate the candidate

Current hot path validates policy, source instruction or pool accounts, mint evidence or RPC state, and available input balance before routing finishes. It does not simulate the signed transaction before send. Older journal records may contain route_simulation_ms and route_final_checks_ms from earlier behavior.

Sync work · required gateCandidate checks

Reject unsupported layouts, mismatched accounts, invalid amounts, missing cached blockhash, and insufficient input balance. The network performs execution and fee checks after submission; a landed transaction can still fail.

05 Send & persist

Recorded timings post_route_ms — winner handling and serialization up to send start. sender_request_ms — submission request through response. post_send_journal_ms — route and signed-transaction writes after the response.

Send starts here receipt_to_send_start_ms
Awaited asyncSender request

Submit and wait for the response. receipt_to_send_response_ms includes this wait; send-start latency does not.

Timing receipt_to_send_start_ms and receipt_to_send_response_ms are cumulative times from payload receipt, not durations to add together.

Awaited async · after submissionSave route → save signed transaction

mark_route and persist_signed run after the sender response, including errors. Journal failures are logged and confirmation continues. A crash before persistence can leave the submitted signature missing from local recovery data. SQLite retains WAL with full durability.

06 Confirm & finish

Recorded timings confirmation_ms — confirmation polling and landing-slot persistence. reconciliation_ms — resulting balance reads, debit/output checks, and outcome persistence. DB operations: record_landed_slot, update_attempt. Logging and timing-writer enqueue have no separate stage timer.

Awaited async · sequentialConfirm → record slot → reconcile → save outcome

The worker waits for confirmation, persists the landing slot, checks resulting balances, and saves the outcome. These steps delay the next observation, not this trade's send start.

Sync workLog timings & try enqueue

Console logging is synchronous. Timing JSON is offered to the background writer with a nonblocking queue operation. Then the worker can process its next observation.

Alongside the worker

BackgroundTiming writer

A separate task awaits database commits. It batches up to 32 available records from a 256-record queue. The trade does not await these writes.

Queue overflow or write failure can drop telemetry with a warning. Pending timing records can be lost at process shutdown. Recovery data never uses this queue.

Timing No per-trade timer for background telemetry writes. db_total_us sums measured DB operations; db_pre_send_us snapshots that sum before sending, and db_post_send_us is the remainder. These are overlapping operation totals, not wall-clock stages.

BackgroundWallet balance cache

Refresh SOL and configured token accounts 250 ms after each refresh finishes. Input balance checks use the cached value; an account without a cached balance cannot execute. Reconciliation reads fresh balances after confirmation.

BackgroundPool catalog refresh

Periodic maintenance refreshes routing candidates independently of the execution worker.

Timing No separate per-trade timer for background catalog maintenance.

BackgroundBlockhash cache refresh

Warm the cache before signal and execution workers start, then refresh one second after each completed refresh. Fetch confirmed blockhash and block height together, with a 1.5-second timeout and more than 20 blocks of remaining validity.

Entries expire two seconds after request start. Failed refreshes do not extend freshness; a cold or stale trade-time lookup fails until the background refresh succeeds. Fresh lookups do not wait for background refresh. Maintenance stops with the service.

Timing No separate per-trade timer for background refresh. Cached preparation is measured by route_shared_preparation_ms.

BackgroundSender connection warming

Mainnet startup warms the Sender connection. Periodic pings then run alongside the worker, waiting 30 seconds between completed warmups.

Timing No separate per-trade timer for startup warmup or background pings.

Reading the timings

Use receipt_to_send_start_ms to compare send latency. DB and route substage durations can overlap; adding them does not reconstruct a timeline. Route substages sum work across attempted candidates, including failures and cancellation. Unstarted timers are omitted; older records may lack newer fields. DB operation entries contain elapsed microseconds and call counts; other fields use milliseconds unless labeled _us.

Average quote time can exceed average receipt-to-send time because candidate timings add overlapping work. Averages are computed separately from available samples for each field, so missing historical timers appear as dashes. Unsupported observations are recorded without submitting a transaction.
